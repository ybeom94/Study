## 1. 서버 프로그래밍의 개념

서버 프로그래밍이란 클라이언트의 요청을 받아 필요한 작업을 수행하고 결과를 반환하는 프로그램을 개발하는 것이다.

### 1-1. 클라이언트와 서버

| 구분 | 역할 |
|---|---|
| Client | 서버에 서비스나 데이터 요청 |
| Server | 요청을 처리하고 결과 반환 |
| Database | 데이터를 지속적으로 저장하고 관리 |

**기본적인 동작 구조**

```text
        Client
           │
           │ Request (요청)
           ▼
        Server
           │
           │ 데이터 조회 및 변경
           ▼
       Database
           │
           │ 처리 결과
           ▼
        Server
           │
           │ Response (응답)
           ▼
        Client
```

**핵심**
- 클라이언트는 요청을 보내고 서버는 요청을 처리한다.
- 서버는 비즈니스 로직을 실행하고 필요한 데이터를 관리한다.
- 데이터베이스는 지속적으로 보관해야 하는 정보를 저장한다.
- 서버는 요청의 유효성을 검증해야 하며 클라이언트의 데이터를 무조건 신뢰해서는 안 된다.

## 2. 게임 서버 시스템 구축

서버 시스템 구축은 서버 프로그램을 실행하고 클라이언트와 통신할 수 있는 환경을 준비하는 과정이다.

### 2-1. 서버 시스템의 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Hardware | CPU, RAM, 저장장치 등 물리적 자원 |
| OS | 프로세스, 메모리, 입출력 등 시스템 자원 관리 |
| IP Address | 네트워크에서 통신 대상을 식별하는 주소 |
| Port | 컴퓨터 내부의 네트워크 서비스 구분 |
| Server Application | 클라이언트의 요청을 처리하는 프로그램 |
| DBMS | 데이터베이스 생성, 조회, 수정 및 관리 |

### 2-2. 프로세스와 스레드

**프로세스(Process)**
- 실행 중인 프로그램의 인스턴스이다.
- 독립적인 가상 주소 공간과 시스템 자원을 가진다.
- 운영체제의 관리 및 스케줄링 대상이다.

**스레드(Thread)**
- 프로세스 내부에서 실행되는 작업 흐름이다.
- 같은 프로세스의 스레드들은 메모리 일부를 공유한다.
- 여러 작업을 동시에 처리하는 데 사용한다.

| 구분 | Process | Thread |
|---|---|---|
| 실행 단위 | 실행 중인 프로그램 | 프로세스 내부 실행 흐름 |
| 메모리 | 프로세스별 주소 공간 | 같은 프로세스의 메모리 공유 |
| 데이터 공유 | 별도의 통신 수단 필요 | 공유 메모리를 통해 가능 |
| 주의사항 | 자원 관리 | 경쟁 상태 및 동기화 |

**핵심**
- 서버는 여러 클라이언트의 요청을 처리해야 한다.
- 멀티스레딩은 동시 요청 처리에 사용할 수 있는 방법 중 하나이다.
- 공유 자원에 동시에 접근하면 데이터 충돌이 발생할 수 있다.
- 스레드 이외에도 비동기 I/O와 이벤트 기반 처리 방식을 활용할 수 있다.

## 3. 네트워크 프로그래밍

네트워크 프로그래밍은 서로 다른 컴퓨터에서 실행되는 프로그램들이 데이터를 송수신하도록 구현하는 기술이다.

### 3-1. TCP/IP

TCP/IP는 인터넷을 비롯한 네트워크에서 통신하기 위한 프로토콜 모음이다.

**대표적인 프로토콜**

| 프로토콜 | 역할 |
|---|---|
| IP | 패킷의 주소 지정 및 전달 |
| TCP | 연결 기반의 신뢰성 있는 데이터 전송 |
| UDP | 비연결 데이터그램 전송 |
| HTTP | 웹 클라이언트와 서버 간 요청·응답 |
| HTTPS | TLS를 적용한 안전한 HTTP 통신 |

### 3-2. TCP와 UDP

| 구분 | TCP | UDP |
|---|---|---|
| 연결 | 연결 지향 | 비연결 지향 |
| 신뢰성 | 재전송 및 순서 보장 | 자체적으로 보장하지 않음 |
| 데이터 단위 | 바이트 스트림 | 데이터그램 |
| 주요 특징 | 신뢰성 중심 | 단순하고 지연 제어에 유리 |
| 대표 활용 | 계정 처리, 웹 통신 | 실시간 게임 상태 전송 등 |

**핵심**
- TCP는 데이터의 신뢰성과 순서가 중요할 때 사용한다.
- UDP는 실시간성이 중요하고 일부 데이터 손실을 허용할 수 있는 상황에 고려한다.
- UDP를 사용할 때 필요한 신뢰성 기능은 애플리케이션에서 별도로 구현할 수 있다.

### 3-3. Socket 통신

소켓(Socket)은 프로그램이 네트워크를 통해 데이터를 주고받기 위한 통신 인터페이스이다.

**TCP 연결 과정**

```text
          Server              Client
             │                   │
       Socket 생성              │
             │                   │
       Port 바인딩              │
             │                   │
       연결 대기                 │
             │◄──── 연결 요청 ───│
             │                   │
       연결 수락                 │
             │                   │
             │◄── 데이터 전송 ───│
             │                   │
             │─── 처리 결과 ────►│
             │                   │
          연결 종료
```

**Java 주요 클래스**

| 클래스 | 역할 |
|---|---|
| `ServerSocket` | TCP 서버 연결 요청 수락 |
| `Socket` | TCP 연결 및 데이터 송수신 |
| `InputStream` | 데이터 읽기 |
| `OutputStream` | 데이터 쓰기 |
| `DatagramSocket` | UDP 데이터 송수신 |

**주의사항**
- TCP는 바이트 스트림이므로 메시지의 경계를 별도로 정의해야 한다.
- 네트워크 통신에서는 연결 실패, 지연, 데이터 손실 등을 고려해야 한다.
- 실제 서버에서는 타임아웃, 연결 종료 및 예외 처리가 중요하다.

## 4. 데이터베이스 프로그래밍

데이터베이스 프로그래밍은 서버가 처리하는 정보를 저장, 조회, 수정, 삭제하는 기능을 구현하는 것이다.

### 4-1. 데이터베이스의 역할

- 프로그램 종료 후에도 데이터 유지
- 사용자 및 서비스 정보 관리
- 여러 사용자 간 데이터 공유
- 데이터의 무결성과 일관성 유지

**DBMS(Database Management System)**

데이터베이스를 생성하고 관리하는 소프트웨어이다.

대표적인 관계형 DBMS에는 Oracle Database, MySQL, PostgreSQL 등이 있다.

### 4-2. CRUD

CRUD는 데이터를 처리하는 네 가지 기본 작업이다.

| 구분 | 의미 | SQL 명령 |
|---|---|---|
| Create | 데이터 생성 | INSERT |
| Read | 데이터 조회 | SELECT |
| Update | 데이터 수정 | UPDATE |
| Delete | 데이터 삭제 | DELETE |

**SQL 예제**

```sql
-- 데이터 조회
SELECT * FROM player;

-- 데이터 생성
INSERT INTO player (id, name)
VALUES (1, 'Player1');

-- 데이터 수정
UPDATE player
SET name = 'Player2'
WHERE id = 1;

-- 데이터 삭제
DELETE FROM player
WHERE id = 1;
```

### 4-3. 트랜잭션(Transaction)

트랜잭션은 여러 데이터베이스 작업을 하나의 논리적인 작업 단위로 처리하는 것이다.

**ACID 특성**

| 특성 | 의미 |
|---|---|
| Atomicity | 작업을 전부 성공시키거나 전부 취소 |
| Consistency | 데이터의 일관성 규칙 유지 |
| Isolation | 동시 실행되는 트랜잭션 간 간섭 제어 |
| Durability | 확정된 변경 사항의 지속성 보장 |

**트랜잭션 처리 흐름**

```text
        작업 시작
            │
            ▼
       데이터 변경
            │
            ▼
       작업 성공 여부
         │       │
        성공    실패
         │       │
         ▼       ▼
       COMMIT  ROLLBACK
         │       │
         ▼       ▼
      변경 확정  변경 취소
```

**핵심**
- 여러 데이터 변경 작업을 하나의 단위로 처리한다.
- 모든 작업이 성공하면 COMMIT으로 확정한다.
- 작업에 실패하면 ROLLBACK으로 취소할 수 있다.
- 동시 요청으로 같은 데이터를 변경할 경우 트랜잭션 격리와 동시성 제어를 고려해야 한다.

## 5. 서버 응용 프로그래밍

서버 응용 프로그래밍은 네트워크, 데이터베이스, 비즈니스 로직을 결합하여 실제 서비스 기능을 구현하는 작업이다.

### 5-1. 서버의 주요 기능

| 기능 | 설명 |
|---|---|
| Authentication | 사용자의 신원 확인 |
| Authorization | 사용자별 접근 권한 검사 |
| Validation | 입력값 및 요청의 유효성 검증 |
| Business Logic | 서비스 규칙에 따른 데이터 처리 |
| Data Access | 데이터베이스 조회 및 변경 |
| Response | 처리 결과를 클라이언트에 반환 |
| Exception Handling | 오류 상황 처리 및 전파 |

### 5-2. 서버 응용 프로그램의 구조

```text
         Client
            │
            ▼
      Network / API
            │
            ▼
      Request Handler
            │
            ▼
      Business Logic
            │
            ▼
       Data Access
            │
            ▼
         Database
            │
            ▼
       처리 결과 반환
```

**각 영역의 역할**

- Network/API : 요청을 수신하고 응답을 전송한다.
- Request Handler : 요청을 분석하고 적절한 기능에 연결한다.
- Business Logic : 인증, 검증 및 서비스 규칙을 실행한다.
- Data Access : 데이터베이스와 통신한다.
- Database : 데이터를 영구적으로 저장하고 관리한다.

**핵심**
- 통신, 비즈니스 로직, 데이터 접근 기능을 분리하는 것이 중요하다.
- 서버는 요청을 검증한 뒤 처리해야 한다.
- 데이터의 일관성을 위해 트랜잭션을 활용할 수 있다.
- 실패한 요청에도 명확한 오류 응답을 제공해야 한다.

## 6. 서버의 안정성과 보안

서버는 여러 클라이언트의 요청을 지속적으로 처리하므로 안정성과 보안이 중요하다.

### 6-1. 동시성과 동기화

**동시성(Concurrency)**
- 여러 작업의 실행을 조정하여 처리하는 특성이다.

**경쟁 상태(Race Condition)**
- 여러 스레드가 공유 자원에 접근할 때 실행 순서에 따라 결과가 달라지는 현상이다.

**동기화(Synchronization)**
- 공유 자원의 접근과 실행 순서를 제어하여 데이터의 일관성을 유지하는 방법이다.

| 동기화 기법 | 주요 특징 |
|---|---|
| synchronized | Java의 상호 배제 및 메모리 가시성 보장 |
| Lock | 명시적으로 잠금 획득 및 해제 |
| Semaphore | 동시 접근 가능한 자원 수 제어 |
| Atomic 클래스 | 일부 값을 원자적으로 처리 |

### 6-2. 예외 처리와 로깅

**예외 처리**
- 잘못된 요청이나 서버 오류에 적절하게 대응한다.
- 필요한 경우 예외를 상위 계층으로 전파한다.
- 외부 자원은 사용 후 안전하게 종료한다.

**로깅(Logging)**
- 서버의 실행 상태 및 오류 정보를 기록한다.
- 장애 발생 시 원인을 추적한다.
- 성능 문제 및 비정상적인 접근을 분석한다.

**기본 보안 원칙**
- 클라이언트 입력값 검증
- 사용자 인증 및 접근 권한 확인
- 비밀번호의 안전한 해시 저장
- HTTPS 등 암호화 통신 사용
- SQL Injection 등의 공격 방지
- 민감한 정보의 로그 및 응답 노출 방지

## ✅ 서버 프로그래밍 핵심 정리

| 학습 영역 | 반드시 이해해야 할 핵심 |
|---|---|
| 서버 기본 구조 | Client, Server, Request, Response |
| 서버 시스템 | OS, Process, Thread, IP, Port |
| 네트워크 | TCP/UDP, Socket, Protocol |
| 데이터베이스 | SQL, CRUD, DBMS |
| 데이터 무결성 | Transaction, ACID |
| 서버 응용 | 인증, 검증, 비즈니스 로직 |
| 동시성 | Race Condition, Synchronization |
| 안정성 | 예외 처리, 로깅, 자원 관리 |
| 보안 | 인증·인가, 입력값 검증, 암호화 |

**최종 학습 정리**

- 서버는 클라이언트의 요청을 받아 처리하고 결과를 반환하는 프로그램이다.
- 서버 시스템은 운영체제, 네트워크, 서버 프로그램, 데이터베이스 등으로 구성된다.
- IP와 Port는 네트워크 통신 대상을 구분하는 데 사용한다.
- 프로세스는 실행 중인 프로그램이며 스레드는 프로세스 내부의 실행 흐름이다.
- TCP와 UDP는 서로 다른 특성을 가진 전송 프로토콜이다.
- Socket은 네트워크를 통해 데이터를 송수신하기 위한 통신 인터페이스이다.
- 데이터베이스는 지속적으로 보관해야 할 정보를 관리한다.
- CRUD는 데이터 생성, 조회, 수정, 삭제 작업을 의미한다.
- 트랜잭션은 여러 데이터베이스 작업을 하나의 논리적 단위로 처리한다.
- 서버 응용 프로그램은 통신, 비즈니스 로직, 데이터 접근을 역할별로 분리하는 것이 좋다.
- 여러 사용자의 요청을 동시에 처리할 때는 동시성과 데이터 일관성을 고려해야 한다.
- 서버의 안정적인 운영을 위해 예외 처리, 로깅, 보안 및 자원 관리가 필요하다.

## 2. 게임 알고리즘 개발

알고리즘(Algorithm)은 특정 문제를 해결하기 위한 명확한 처리 절차이다.

게임에서는 데미지 계산, 몬스터 탐색, 아이템 정렬, 경로 탐색 등에 활용한다.

### 2-1. 자료구조(Data Structure)

자료구조는 데이터를 저장하고 관리하는 방식이다.

| 자료구조 | 특징 | 활용 예시 |
|---|---|---|
| Array | 고정된 길이의 데이터 저장 | 인벤토리 슬롯 |
| List | 순서가 있는 데이터 목록 | 퀘스트 목록 |
| Stack | LIFO, 후입선출 | 이전 메뉴 복귀 |
| Queue | FIFO, 선입선출 | 작업 대기열 |
| HashMap | Key-Value 데이터 관리 | ID 기반 데이터 조회 |
| Graph | 노드와 간선으로 관계 표현 | 맵 및 경로 탐색 |

**자료구조의 기본 개념**

```text
[Stack] LIFO

    ┌──────┐
    │  30  │ ← 마지막 삽입, 먼저 제거
    ├──────┤
    │  20  │
    ├──────┤
    │  10  │
    └──────┘


[Queue] FIFO

 삽입 → [10][20][30] → 제거
          먼저 들어온 데이터부터 제거
```

### 2-2. 주요 알고리즘

| 알고리즘 | 설명 | 활용 예시 |
|---|---|---|
| Linear Search | 데이터를 순차적으로 탐색 | 대상 검색 |
| Binary Search | 정렬된 데이터의 탐색 범위를 절반씩 축소 | 데이터 검색 |
| Sorting | 데이터를 특정 기준에 따라 정렬 | 랭킹 정렬 |
| BFS | 가까운 노드부터 탐색 | 최단 경로 탐색 |
| DFS | 한 방향으로 깊게 탐색 | 맵 연결 탐색 |
| A* | 휴리스틱을 이용한 경로 탐색 | NPC 이동 |

### 2-3. 시간 복잡도(Big O)

시간 복잡도는 입력 데이터의 크기에 따라 알고리즘의 작업량이 얼마나 증가하는지 표현하는 방법이다.

| 시간 복잡도 | 특징 | 대표 예시 |
|---|---|---|
| O(1) | 일정한 작업량 | 배열 인덱스 접근 |
| O(log n) | 로그 비율로 증가 | 이진 탐색 |
| O(n) | 데이터 개수에 비례 | 선형 탐색 |
| O(n log n) | 효율적인 정렬의 대표적 복잡도 | 병합 정렬 |
| O(n²) | 데이터 개수의 제곱에 비례 | 이중 반복문 |

### 2-4. Java 알고리즘 예제

**데미지 계산**

```java
public class DamageCalculator {

    public static int calculate(int attack, int defense) {
        return Math.max(1, attack - defense);
    }

    public static void main(String[] args) {
        int damage = calculate(100, 30);

        System.out.println(damage); // 70
    }
}
```

**핵심**
- 자료구조는 데이터를 효율적으로 관리하기 위한 방법이다.
- 알고리즘은 데이터를 처리하고 문제를 해결하는 절차이다.
- 데이터의 크기와 처리 목적에 적합한 알고리즘을 선택해야 한다.
- 시간 복잡도와 공간 복잡도는 성능을 판단하는 중요한 기준이다.

**게임 UI의 대표적인 구성**

### 3-2. 이벤트 기반 프로그래밍(Event-Driven Programming)

이벤트 기반 프로그래밍은 특정 동작이 발생했을 때 등록된 기능을 실행하는 방식이다.

**이벤트 처리 흐름**

```text
       사용자 입력
            │
            ▼
       Event 발생
            │
            ▼
      Event Handler
            │
            ▼
       Game Logic
            │
            ▼
       데이터 변경
            │
            ▼
        UI 갱신
```

**이벤트 처리 예제**

```java
interface ClickListener {
    void onClick();
}

class Button {

    private ClickListener listener;

    public void setOnClickListener(ClickListener listener) {
        this.listener = listener;
    }

    public void click() {
        if (listener != null) {
            listener.onClick();
        }
    }
}
```

**사용 예제**

```java
Button button = new Button();

button.setOnClickListener(() -> {
    System.out.println("버튼 클릭");
});

button.click();
```

**핵심**
- UI는 사용자 입력과 정보 출력을 담당한다.
- 이벤트를 이용하면 특정 상황에 필요한 기능을 실행할 수 있다.
- UI 표시와 데이터 처리 로직은 적절하게 분리하는 것이 좋다.
- 사용자에게 명확하고 일관된 피드백을 제공해야 한다.

## 4. 게임 인공지능 프로그래밍

게임 인공지능(Game AI)은 NPC나 게임 객체가 상황에 따라 행동을 결정하도록 구현하는 기술이다.

게임 AI에는 FSM, Behavior Tree, 경로 탐색 등 다양한 기술을 사용할 수 있다.

### 4-1. 주요 게임 AI 기술

| 기술 | 설명 | 활용 예시 |
|---|---|---|
| FSM | 상태에 따라 행동 변경 | 대기, 추적, 공격 |
| Behavior Tree | 트리 구조로 행동 판단 | 복잡한 NPC 행동 |
| Pathfinding | 목적지까지 이동 경로 탐색 | 몬스터 이동 |
| A* Algorithm | 휴리스틱 기반 경로 탐색 | 장애물 회피 경로 |
| Decision Making | 조건에 따른 행동 결정 | 공격 및 도주 판단 |

### 4-2. FSM(Finite State Machine)

FSM은 유한한 상태와 전환 조건을 이용하여 객체의 행동을 관리하는 구조이다.

**FSM의 기본 구조**

```text
            대상 발견
       ┌──────────────────┐
       │                  ▼
    [IDLE]             [CHASE]
      대기               추적
       ▲                  │
       │                  │ 공격 범위 진입
       │                  ▼
       │               [ATTACK]
       │                 공격
       │                  │
       └──────────────────┘
          대상 상실 시 대기

※ 공격 범위 이탈 시 CHASE로 전환 가능
```

**Java FSM 예제**

```java
enum State {
    IDLE,
    CHASE,
    ATTACK
}

public class EnemyAI {

    private State state = State.IDLE;

    public void update(double distance) {

        if (distance <= 2) {
            state = State.ATTACK;

        } else if (distance <= 10) {
            state = State.CHASE;

        } else {
            state = State.IDLE;
        }

        System.out.println(state);
    }
}
```

**핵심**
- FSM은 상태와 상태 전환 조건으로 행동을 제어한다.
- Behavior Tree는 복잡한 행동 조건을 트리 구조로 관리한다.
- 경로 탐색은 목적지까지 이동할 경로를 계산한다.
- 게임 AI는 반드시 머신러닝을 사용하는 것은 아니다.
- NPC의 행동 복잡도에 맞는 구조를 선택하는 것이 중요하다.

## 5. 게임엔진 프로그래밍

게임엔진 프로그래밍은 게임 엔진이 제공하는 기능을 활용하거나 확장하여 게임 시스템을 구현하는 작업이다.

### 5-1. 게임 엔진의 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| Rendering | 2D·3D 그래픽 출력 |
| Physics | 물리 연산 및 충돌 처리 |
| Input | 키보드, 마우스, 게임패드 입력 |
| Animation | 애니메이션 재생 및 제어 |
| Audio | 사운드 출력 |
| Scene | 게임 공간 및 객체 관리 |
| Scripting | 게임 로직 구현 |
| Resource Management | 모델, 텍스처 등의 리소스 관리 |

### 5-2. Game Loop

Game Loop는 게임의 입력, 상태 갱신, 화면 출력을 반복적으로 처리하는 실행 구조이다.

**기본적인 게임 루프**

```text
       게임 시작
           │
           ▼
      Input 처리
           │
           ▼
      Game Update
           │
           ▼
     Physics Update
           │
           ▼
       Rendering
           │
           ▼
       다음 프레임
           │
           └──── 반복
```

※ 실제 엔진에서는 물리 갱신이 고정 시간 간격으로 수행되는 등 실행 구조가 다를 수 있다.

### 5-3. Delta Time

Delta Time은 이전 갱신 이후 경과한 시간이다.

프레임 속도에 따라 이동량이 달라지는 문제를 줄이기 위해 사용한다.

**기본 계산**

```java
position += speed * deltaTime;
```

| 변수 | 의미 |
|---|---|
| position | 현재 위치 |
| speed | 초당 이동 속도 |
| deltaTime | 이전 갱신 이후 경과 시간 |

**핵심**
- Game Loop는 게임 실행의 기본 흐름을 관리한다.
- Delta Time은 경과 시간을 반영한 이동과 갱신에 활용한다.
- 물리 계산과 일반 게임 갱신은 서로 다른 실행 주기를 사용할 수 있다.

### 5-4. 컴포넌트 기반 설계

컴포넌트(Component)는 게임 객체의 기능을 독립적인 단위로 분리하여 조합하는 방식이다.

**객체와 컴포넌트 구조**

```text
           Player Object
                 │
       ┌─────────┼──────────┐
       │         │          │
       ▼         ▼          ▼
   Transform  Renderer   Collider
       │         │          │
     위치      화면 출력    충돌 처리
       │
       ▼
 PlayerController
       │
     이동 로직
```

**핵심**
- 게임 객체는 여러 컴포넌트를 조합하여 구성할 수 있다.
- 기능별 분리는 재사용성과 유지보수성을 높인다.
- 게임 엔진은 복잡한 기반 시스템을 제공하여 게임 로직 구현에 집중할 수 있도록 돕는다.

## 6. 플랫폼 응용 프로그래밍

플랫폼 응용 프로그래밍은 운영체제와 하드웨어 환경에 맞게 프로그램을 구현하고 실행할 수 있도록 만드는 작업이다.

### 6-1. 플랫폼별 특징

| 플랫폼 | 입력 방식 | 주요 고려사항 |
|---|---|---|
| PC | 키보드, 마우스, 게임패드 | 다양한 하드웨어, 그래픽 설정 |
| Mobile | 터치, 센서 | 배터리, 발열, 메모리 |
| Console | 게임패드 | 플랫폼 요구사항, 성능 제약 |

### 6-2. 크로스 플랫폼(Cross-platform)

크로스 플랫폼은 하나의 애플리케이션을 여러 운영체제나 장치에서 실행할 수 있도록 개발하는 방식이다.

**기본 구조**

```text
           공통 Game Logic
                  │
          플랫폼별 기능 분리
                  │
       ┌──────────┴──────────┐
       │                     │
       ▼                     ▼
    PC Platform         Mobile Platform
       │                     │
       ▼                     ▼
   키보드/마우스            터치 입력
```

**핵심**
- 공통 기능은 재사용하고 플랫폼별 기능은 분리한다.
- 플랫폼마다 입력 장치와 하드웨어 제약이 다르다.
- 동일한 게임이라도 플랫폼 특성에 따른 최적화가 필요할 수 있다.

### 6-3. 최적화(Optimization)

최적화는 제한된 하드웨어 자원을 효율적으로 사용하여 프로그램의 성능을 개선하는 작업이다.

| 항목 | 설명 |
|---|---|
| FPS | 초당 화면에 표시하는 프레임 수 |
| CPU Usage | CPU 연산 자원 사용량 |
| GPU Usage | 그래픽 처리 자원 사용량 |
| Memory Usage | 프로그램 메모리 사용량 |
| Draw Call | 그래픽 명령 제출과 관련된 작업 |
| Profiling | 실행 성능 및 병목 구간 측정 |
| Build | 실행 가능한 프로그램 생성 |
| Deployment | 대상 플랫폼으로 프로그램 배포 |

**최적화 과정**

```text
       성능 문제 발생
              │
              ▼
        Profiling 수행
              │
              ▼
        병목 구간 확인
              │
              ▼
         원인 분석
              │
              ▼
         코드 및 구조 개선
              │
              ▼
           재측정
```

**핵심**
- 성능 문제는 먼저 측정한 뒤 분석해야 한다.
- CPU, GPU, 메모리 사용량을 각각 확인한다.
- 플랫폼별 제약 조건에 맞게 자원을 관리한다.
- 최적화의 목적은 기능을 유지하면서 불필요한 작업을 줄이는 것이다.

## 7. 응용 프로그래밍과 서버 프로그래밍의 관계

응용 프로그래밍과 서버 프로그래밍은 서로 다른 역할을 수행하지만 하나의 서비스를 구성하기 위해 함께 사용될 수 있다.

### 7-1. 주요 차이

| 구분 | 응용 프로그래밍 | 서버 프로그래밍 |
|---|---|---|
| 주요 목적 | 사용자 기능과 게임 동작 구현 | 요청 처리 및 공통 데이터 관리 |
| 대표 기능 | 캐릭터 이동, UI, NPC | 인증, 데이터 저장, 게임 상태 검증 |
| 핵심 기술 | 알고리즘, 게임 엔진, AI | 네트워크, DB, 동시성 |
| 주요 관심사 | 반응성, 사용성, 실행 성능 | 데이터 일관성, 안정성, 보안 |

### 7-2. 클라이언트와 서버의 연동 구조

```text
         Game Client
              │
              ▼
         사용자 입력
              │
              ▼
          Game Logic
              │
              │ 요청 전송
              ▼
          Game Server
              │
              ▼
        요청 유효성 검증
              │
              ▼
         데이터 처리
              │
              ▼
           Database
              │
              │ 처리 결과
              ▼
          Game Server
              │
              │ 응답 전송
              ▼
          Game Client
              │
              ▼
         UI / 상태 갱신
```

**핵심**
- 응용 프로그램은 입력과 게임 동작을 처리한다.
- 서버는 필요한 요청 검증 및 데이터 처리를 담당한다.
- 통신을 통해 클라이언트와 서버의 상태를 연결한다.
- 실제 역할 분담은 게임의 네트워크 아키텍처에 따라 달라진다.

## ✅ 응용 프로그래밍 핵심 정리

| 학습 영역 | 반드시 이해해야 할 핵심 |
|---|---|
| Application Programming | 사용자 기능 및 게임 시스템 구현 |
| Data Structure | 데이터 저장 및 관리 구조 |
| Algorithm | 문제 해결을 위한 처리 절차 |
| Big O | 알고리즘의 시간 복잡도 |
| UI/UX | 사용자 입력과 정보 전달 |
| Event | 특정 동작 발생 시 기능 실행 |
| FSM | 상태와 전환 조건에 따른 행동 제어 |
| Behavior Tree | 트리 구조의 행동 판단 |
| Pathfinding | 목적지까지 이동 경로 계산 |
| Game Engine | 게임 실행을 위한 기반 기능 |
| Game Loop | 입력·상태 갱신·출력의 반복 |
| Delta Time | 경과 시간을 반영한 갱신 |
| Component | 객체 기능의 독립적인 구성 요소 |
| Cross-platform | 여러 플랫폼에서의 프로그램 실행 |
| Profiling | 성능 측정 및 병목 분석 |
| Optimization | 실행 성능 및 자원 사용 개선 |

**최종 학습 정리**

- 응용 프로그래밍은 사용자가 실제로 이용하는 기능을 구현하는 작업이다.
- 알고리즘은 문제를 해결하는 절차이며 자료구조는 데이터를 관리하는 방식이다.
- 시간 복잡도는 데이터가 증가할 때 알고리즘의 작업량을 판단하는 기준이다.
- UI는 사용자와 프로그램의 상호작용 수단이고 UX는 사용자가 경험하는 전체 과정이다.
- 이벤트 기반 프로그래밍은 입력이나 특정 상황에 따라 기능을 실행한다.
- 게임 인공지능은 NPC가 게임 규칙에 따라 판단하고 행동하도록 구현한다.
- FSM은 상태와 전환 조건을 통해 객체의 행동을 관리한다.
- Behavior Tree는 복잡한 행동을 트리 구조로 표현한다.
- 경로 탐색 알고리즘은 목적지까지 이동할 경로를 계산한다.
- 게임 엔진은 렌더링, 물리, 입력, 애니메이션 등의 기반 기능을 제공한다.
- Game Loop는 입력 처리, 상태 갱신, 화면 출력 과정을 반복한다.
- Delta Time은 경과 시간을 반영한 이동과 갱신에 사용한다.
- 컴포넌트 기반 설계는 객체의 기능을 나누어 조합하는 방식이다.
- 플랫폼 응용 프로그래밍은 실행 환경과 하드웨어 특성을 고려한다.
- 크로스 플랫폼 개발은 공통 기능을 재사용하면서 플랫폼별 기능을 분리한다.
- 최적화는 프로파일링을 통해 성능 문제를 측정하고 개선하는 과정이다.
- 응용 프로그래밍과 서버 프로그래밍은 서로 연동하여 하나의 게임 서비스를 구성할 수 있다.
- 응용 프로그래밍의 핵심은 각 기능을 독립적으로 구현하는 것뿐 아니라 시스템 사이의 관계를 이해하고 효율적으로 연결하는 것이다.
